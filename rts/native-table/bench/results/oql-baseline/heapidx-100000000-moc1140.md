# Ledger with one heap index written on chain, 100,000,000 rows, moc 1.14.0

OQL: commit `bb5a23f` of `github.com/caffeinelabs/oql-prototype` ("fix: scope compiled predicates to one row stream (#107)", 2026-10-09), extracted with `git archive bb5a23f` into a scratch copy (README.md, "Setting up the OQL copies", gives the commands); dependencies core 2.6.0, jayson 0.1.1, bench 2.0.1 (`mops install`).
Replica: PocketIC 14.0.0 (`pocket-ic-server 14.0.0`, DFINITY's local test replica of the Internet Computer, the binary mops installs for OQL's `[toolchain]` pin), on an Apple M3 (macOS, 16 KiB host pages); dfx, DFINITY's SDK command-line tool, which runs a local replica of its own, was not used.
Compiler: `mops toolchain bin moc` of the copy: moc 1.14.0 (OQL's `[toolchain]` pin) and, in a second copy whose `mops.toml` pins moc 1.16.1, moc 1.16.1.

Rows: OQL's scale-bench ledger generator `bigRow(k)` (bench/scale/main.mo and image.mjs): account_from = splitmix64(k) mod 100,000; account_to; account_spender (null on odd k); amount_e8s; day = floor(k / 3,000); five `#nat` columns. Canister: `bench/scale/oqlbars.mo`, copied from `src/oqlbars.mo` and built as `bench/scale/oqlbars.wasm` (README.md, "Setting up the OQL copies"; not `src/oqlbars-deadkeys.mo`, whose extra table `dkt` was added after this run had installed its canister and changes the counts), OQL's `bench/scale/main.mo` plus an `op` endpoint (one measured operation per message), a table `ledger1` with one heap index, and `appendBig`; built with moc `--default-persistent-actors -fshared-code --max-stable-pages 1638400` (OQL's scale build without `--force-gc`). `ImportData.mo` of the scratch copy records the in-method instructions of `putSegment`, `putIndexChunk` and `commitIndex` (two counter reads added; source in `src/ImportData.mo`). Here no load: the rows are appended on chain (`genIndexed1`, 50,000 per message) into `ledger1`, an `OQL.Table` with the heap `account_from #hash` index (auto-flush every 50,000 rows), unlike the uploads, which go through OQL's shipped producer (`tools/oql-ingest/lib.mjs`: `uploadRows`, `putIndexSegment`, in flight 1), so each message's cycles are read alone. Queries are real query calls of `measure(qJson)` (the counter around `Executor.runWith`, JSON parsing outside).

Page fees: PocketIC on this host charges the dirty-page fee per dirty 16 KiB host page (calibrated: one write into each of p pages 4 KiB apart costs ceil(p/4) fees of 4,000; a message that does nothing dirties 3 host pages). `pages16` is that count, derived per message from its cycles: cycles = fee + 2 x (mutator + collector + 4,000 x pages16 + 19), fee = 5,000,000 through the relay canister, or the ingress fee calibrated on the same canister (the residue 19 is constant in every message, column `resid`). On the IC's own hosts the fee is per 4 KiB page, between pages16 and 4 x pages16 per message. `charged16` = in-method + the message's collection + 4,000 x pages16; `op16` = the same less the 3 host pages of a message that does nothing.

Built: 100,000,000 rows, 2,000 segments, heap 1,471,218,616 B, 16524 s.

Queries: the rows labeled `(collector as the build left it)` ran straight after the build; the driver then sent `tick` messages until the collector was idle (`settle` in `src/lib.mjs`: 3 ticks, 1,236 collector instructions) and ran the rest.
